# H5 剧本:计划异常日(pb4 人工版)

> **定位**:面向 H5 验证台的剧本式操作说明,是自动化剧本
> `mse/tools/pb4_plan_disruption.py`(50 项校验)的**人工操作版**——人照着 UI 能点出
> 与脚本相同的结果。全程只用浏览器界面(不发 API、不碰数据库),每步给出**预期结果**
> 与**结果说明**(这步验证了什么系统机制)。
> **剧情**:计划员最倒霉的一天。客户来电撤单又反悔(撤单/恢复/重接收三段);
> 紧急插单、换单;VIN-PD01 下到 03 想调序被拦,退回 01 才调成,一路推到
> 05 再调序被原生规则 + WASM 沙盒双拦截;统计员误报工,冲正后达成率回摆;
> 排序冻结令一下,换单立刻被 R-SEQ-FROZEN 挡在门外。
> **配套**:主流业务的一天见《H5业务流模拟操作手册.md》;异常/边界专项见
> 《H5人工验证测试方案.md》;脚本化回归见《剧本自动化回归.md》。

| 0.2 | **不跑** `run_demo.bat`(与脚本的自建空库对齐) | 事件流保持为空 |
| 0.3 | 确认顶部凭证 = `ui-token` | —— |

**角色扮演**(actor 字段体现"谁",全程不用切账号):

| 角色 | 名字(actor 填) | 主要负责的视图 |
|---|---|---|

## 第一幕 撤单与恢复(计划员,客户电话来回,8:05)

**剧情**:VIN-PD01 刚接收,客户来电撤单;十分钟后悔,恢复;重接收归档。

| 步 | 操作 | 预期结果 | 结果说明 |
|---|---|---|---|
| 1.1 | 打开 **V-ORDER-A1**,点「+发起事件」选 `OrderReceived`:id=`VIN-PD01`、actor=`planner-wang`、车型=`SUV-A`、订单状态=`接收`、交付期=`2026-09-12` | 绿色 settled 回执;A1 行 订单状态=接收 | —— |
| 1.2 | A1 的 VIN-PD01 行上点 `OrderRevoked`,订单状态选 `取消`,提交;**记下回执 event_id** | settled;A1 行 订单状态=取消 | 撤单是新事件,不是删行 |
| 1.3 | 点「+发起事件」选 `OrderRevokeReversed`:id=`VIN-PD01`、actor=`planner-wang`、订单状态=`接收`、corrects 填 1.2 记下的撤单事件号 | settled;A1 行状态回到 **接收** | 修正类型必须能写它要修正的属性(订单状态写授权含 OrderRevokeReversed——剧本抓出并修复过的 seeds 缺漏,见《剧本自动化回归.md》§5) |
| 1.4 | A1 行上点 `OrderReReceived`:车型=`SUV-A`、订单状态=`接收`、交付期=`2026-09-12` | settled | 重接收归档,恢复写入随它落 |
| 1.5 | 展开右侧事件流 | OrderRevoked / OrderRevokeReversed / OrderReReceived 三段都在,恢复行带 corrects | 撤单/恢复/重接收三段永存,客户怎么反悔都有账 |

## 第二幕 插单与换单(计划员,8:40)

**剧情**:三台车定序;一张 EV 紧急插到 2 号位;PD01 与 PD03 换单。

| 步 | 操作 | 预期结果 | 结果说明 |
|---|---|---|---|
| 2.1 | 打开 **V-SEQ-A2**,对 VIN-PD01 行点 `SequenceAdjusted`:序列号=`1` | settled | 调序 = 写"序列号"属性的新事件 |
| 2.2 | **V-ORDER-A1** 接收 `VIN-PD02`(车型 `Sedan-B`、订单状态 `接收`、交付期 `2026-09-15`);回 A2 定序 `2` | settled ×2 | —— |
| 2.3 | 同法接收 `VIN-PD03`(车型 `MPV-C`、交付期 `2026-09-18`),定序 `3` | A2 三行序列号 1/2/3 就位 | —— |
| 2.4 | A2 点「+发起事件」选 `OrderInserted`:id=`VIN-PD04`、actor=`planner-wang`、车型=`EV-D`、序列号=`2`、优先级=`1`、交付期=`2026-09-11` | settled;A2 插单行可见(序列号=2,优先级=1) | 插单是自带序列号/优先级的接收事件 |

## 第三幕 退回再调与 05 双拦截(计划员 vs 状态机,9:30)

**剧情**:VIN-PD01 计划下到 03 想调序——被拦;退回 01 才调成;一路推到 05 再调,
原生规则与 WASM 沙盒一起说"不"。

| 步 | 操作 | 预期结果 | 结果说明 |
|---|---|---|---|
| 3.1 | 打开 **V-PLAN-A3**,对 VIN-PD01 行点 `PlanReleased`:「计划状态」下拉**只有 01**,提交;再点选 `02`;再点选 `03` | 三次 settled,行状态 01→02→03;每次下拉只给当前合法的下一步 | 合法选项由 R-PLAN-RELEASE 试探下发:界面给不了非法值 ⇒ API 也结算不了(读写一致性) |
| 3.2 | 03 状态下对该行点 `SequenceAdjusted`,序列号填 `9`,提交 | **红色拦截回执**:R-PLAN-ADJUST"03/04 须退回再调整,05 绝对禁止调整";事件流无新增 | L3 规则拦截:候选预演否决,零事件零污染 |
| 3.3 | 行上点 `PlanRolledBack`:「计划状态」选 `01` | settled,退回 01 | 退回本身是新事件 |
| 3.4 | 再点 `SequenceAdjusted`,序列号=`1` | **settled** | 同一份规则:退回 01 后调序合法——拦与放都是规则说了算 |
| 3.5 | 连续 `PlanReleased`:`02`→`03`→`04`→`05` | 四次 settled,状态到 05(完工关闭) | —— |
| 3.6 | 05 状态下点 `SequenceAdjusted`,序列号填 `7`,提交 | **红色拦截回执**,violations **两条**:`R-PLAN-ADJUST:…05 绝对禁止调整` 与 `R-PLAN-ADJUST-WASM:…05 绝对禁止`;事件流里**没有**序列号=7 的调序 | 双拦截:jsonlogic 原生沙盒与 WASM 沙盒同一立法、各说一遍(规则可移植性的实证);被拒候选零污染 |

## 第四幕 误报工冲正:达成率回摆(统计员,13:10)

**剧情**:产线计划 100 件,报工 2 件达成率 0.02;操作工误把实际产量报成 3,
统计员冲正,指标回摆。

| 步 | 操作 | 预期结果 | 结果说明 |
|---|---|---|---|
| 4.1 | **V-ORDER-A1** 点「+发起事件」`OrderReceived`:id=`总装线`、actor=`planner-wang`、车型=`混流产线`、计划产量=`100` | settled | 产线也是本体;计划产量写授权含 OrderReceived(基线落法与 demo 同) |
| 4.2 | 「+发起事件」选 `CompositionDeclared`:id=`总装车间`、actor=`statistician`,aggregates 填 JSON `[{"key":"实际产量","from":"总装线"},{"key":"计划产量","from":"总装线"}]` | settled | 属性多属声明:车间的这两个键聚合自总装线 |
| 4.3 | **V-COUNT-E2** 点「+发起事件」`CountUpdated`:id=`总装线`、actor=`statistician`、首次合格数=`2` | settled | FTT 分子就位 |
| 4.4 | 打开 **V-EFF-A6**,看 总装线 行 | 计划产量=`100` | —— |
| 4.5 | A6 行上点 `ProductionReported`:id=`总装线`、actor=`op-zhang`、报工数量=`2`、实际产量=`2` | settled;A6 行 实际产量=2、**达成率=0.02**;打开 **V-QUALITY-F16** 看总装线行:**FTT=1.0** | 派生:R-KPI-002 达成率=实际/计划、R-KPI-003 FTT=首次合格数/实际产量,报工事件驱动重算 |
| 4.6 | 误报工:A6 行上再点 `ProductionReported`:报工数量=`1`、实际产量=`3`;**记下回执 event_id** | settled;达成率立刻变 **0.03** | 误报也是事实,先入树、先生效 |
| 4.7 | 打开 **V-REPORT-A7**,在流水里找到 4.6 那条误报行,点行内 **`ReportReversed`**(corrects 已自动填好),实际产量填 `2`,提交 | settled;A6 达成率回摆 **0.02**;F16 的 FTT 回摆 **1.0**;A7 流水里误报与冲正**同列可见**(冲正行红边) | 修正链 + 派生随动:冲正事件同样驱动 derive 重算,指标随事实链回退;流水 fold=L1+L2 |

## 第五幕 排序冻结(计划员,15:20)

**剧情**:冻结令下到 VIN-PD03,再想拿它换单,立刻被挡。

| 步 | 操作 | 预期结果 | 结果说明 |
|---|---|---|---|
| 5.1 | **V-SEQ-A2** 对 VIN-PD03 行点 `OrderFrozen`(冻结状态自动预填"已冻结"●),提交 | settled;A2 行 冻结状态=已冻结 | presets:类型语义自带的写入,表单不用手选 |
| 5.2 | A2 点「+发起事件」选 `OrderSwapped`:id 填 `VIN-PD03,VIN-PD02`(**多目标,逗号分隔**,id 框标签有提示)、actor=`planner-wang`、序列号=`5`,提交 | **红色拦截回执**:R-SEQ-FROZEN"已冻结订单禁止调序/换单";事件流里 OrderSwapped 数量不增;A2 行 VIN-PD03 序列号仍=1、冻结状态=已冻结 | 多目标形态在此原样演示(扁平键对所有目标同写);规则对 writes 里**每个目标**逐个预演,命中冻结即整体拒;被拦候选零污染 |

## 结果总览(演完后的系统状态)

- 撤单/恢复/重接收、误报/冲正都是"三段永存",corrects 因果链完整;
- 状态机两处拦截(03 调序、05 调序)+ 冻结拦截,全部 L3 零污染;05 处额外演示
  **原生 + WASM 双沙盒同一立法**;
- 达成率/FTT 随报工派生、随冲正回摆——派生量不是缓存,是事实链的函数;
- 判定口诀同前:**界面上能点的,API 就能结算;界面上被拦的,API 也结算不了**。

## 常见问题

- **PlanReleased 下拉里没有想要的状态**:那不是 bug——合法选项随当前状态收敛(03 时只有 01 退回 / 04 推进)。按钮灰了悬停看理由。
- **OrderSwapped 的 id 怎么填两台车**:多目标类型的 id 框接受逗号分隔,如 `VIN-PD03,VIN-PD02`;注意属性键会对所有目标写同一组值(互换请用两笔 SequenceAdjusted)。
- **aggregates 怎么填**:JSON 文本框,填 `[{"key":"实际产量","from":"总装线"}]` 这样的数组。
- **数据想重来**:停服务器删两个 db 文件即可(本剧本不依赖 demo 背景)。
