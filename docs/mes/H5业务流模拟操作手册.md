## 第一幕 早会接单与排产(计划员,8:00)

**剧情**:ERP 昨夜下达 2 个新订单,计划员接收、排序、冻结、下发。

| 步 | 操作 | 预期结果 | 结果说明 |
|---|---|---|---|
| 1.1 | 打开 **V-ORDER-A1**,点「+发起事件」选 `OrderReceived`:id=`VIN-LBV0101`、actor=`planner-wang`、车型=`SUV-A`、交付期=`2026-09-10` | 绿色 settled 回执,订单出现在列表 | 本体诞生 = 首个携带该 id 的事件,系统无独立"新建"操作 |
| 1.2 | 同样方式接收 `VIN-LBV0102`(车型 `Sedan-B`) | 列表 5 个订单 | —— |
| 1.3 | 打开 **V-SEQ-A2**(生产排序),对 VIN-LBV0101 点 `SequenceAdjusted`:序列号=`1` | settled;序列号列更新 | 调序是写"序列号"属性的新事件,不是改记录 |
| 1.4 | 对 VIN-LBV0102 点 `SequenceAdjusted`:序列号=`2` | 同上 | —— |
| 1.5 | 打开 **V-PLAN-A3**,对 VIN-LBV0101 点 `PlanReleased` | 「计划状态」下拉**只有 `01` 可选**;提交后行状态变 01 | 合法选项由状态机规则试探下发;界面给不了非法值 ⇒ API 也结算不了非法值(读写一致性) |

## 结果总览(全天演完后的系统状态)

- 事件树:全部业务动作(含规则触发的锁车/报警/返修)按序在树,无一条是"修改";
- 拦截记录:B4/F10/信任/状态机的被拒不进树,只在拦截视图可见;
- 五个视角对同一事实一致:列表(终态)、流水(纵切)、追溯(遍历)、看板(上卷)、拦截(候选);
- 判定口诀:**界面上能点的,API 就能结算;界面上被拦的,API 也结算不了**——按钮与校验是同一份规则。

## 常见问题

- **视图红了/提示缺参数**:遍历类视图(V-TRACE-B5/F14)需要 entity;参数引导页可直接点本体快捷按钮。
- **按钮是灰的**:悬停看原因(规则理由/当前状态无合法值)——这就是规则在工作。
- **提交被拦**:读回执的 layer 与 violations——L2 是形式/字典问题(键、值域、信任级),L3 是业务规则不允许。
- **数据想重来**:停服务器删两个 db 文件即可。
