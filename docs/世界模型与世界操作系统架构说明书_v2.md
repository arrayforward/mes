# 世界模型与世界操作系统架构说明书

> **版本**: v2.0  
> **定位**: 面向多智能体、高动态、可审计的符号化世界系统  
> **核心修正**: 前四棵为数据结构底座（硬骨架），后三棵为业务逻辑系统（软逻辑），非树结构。

---

## 1. 架构愿景

本架构旨在构建一个**可精确操作、可因果审计、可长期演化**的数字世界系统。它不追求用单一模型"理解一切"，而是将世界的不同维度解耦为专门的数据结构与运行时，让生成式AI（LLM/神经场）与符号系统各尽其职。

**关键认知**:
- **世界模型（World Model）** = 世界的"数据库 + 本体论"，回答"是什么、在哪里、发生了什么"。
- **世界操作系统（World OS）** = 世界的"运行时 + 事务系统"，回答"如何演化、能否发生、为何如此"。
- **LLM/生成式模型** = "翻译官与感知器"，连接人类意图与符号宇宙，但不直接操作原子状态。

---

## 2. 总体架构

### 2.1 三层架构

```
┌─────────────────────────────────────────────────────────────┐
│  L2 认知接口层（Cognitive Interface）                        │
│  ├─ LLM 自然语言理解（意图解析、目标消歧、计划生成）          │
│  ├─ 生成式场模型（NeRF/3DGS/神经信道预测，连续场推断）        │
│  └─ 感知表征器（视频/点云/传感器 → 结构化候选表征）          │
└──────────────────────────┬──────────────────────────────────┘
                           │ 符号化指令 / 场数据
┌──────────────────────────▼──────────────────────────────────┐
│  L1 世界模型层（World Model）— 符号记忆层                    │
│  ├─ 四棵数据结构底座（硬骨架）：语义 / 实体 / 时空 / 事件因果  │
│  └─ 三大业务逻辑系统（软逻辑）：规则 / 意图 / 价值            │
└──────────────────────────┬──────────────────────────────────┘
                           │ 事件 / 状态变更 / 规则校验
┌──────────────────────────▼──────────────────────────────────┐
│  L0 世界操作系统层（World OS）— 运行时层                       │
│  ├─ 时钟调度器（物理/逻辑/叙事/因果 多时钟域）                │
│  ├─ 事件总线（原子队列 + 因果DAG + 反事实沙盒）               │
│  ├─ 执行引擎（规则 / 物理 / 行为 / 叙事）                     │
│  ├─ 状态管理器（内存快照 + WAL + 检查点 + 分支）              │
│  └─ 接口网关（LLM适配器 / 人类接口 / 外部系统API）            │
└─────────────────────────────────────────────────────────────┘
```

## 3. 世界模型层（L1）

### 3.1 架构总览

| 层级 | 组件 | 本质 | 核心问题 | 数据形态 |
|------|------|------|---------|---------|
| **数据结构底座** | 语义图谱树 | 知识图谱 | 是什么？意味着什么？ | 本体+规则，有向图 |
| | 实体搜索树 | 索引结构 | 是谁？当前状态？ | 实体实例，HashMap/B+树 |
| | 时空索引树 | 空间索引 | 在哪里？何时？轨迹？ | 4D索引，锚点层级 |
| | 事件因果树 | 因果图 | 为什么？导致什么？ | 因果DAG + 概率 + 反事实 |
| **业务逻辑系统** | 规则/约束系统 | 规则引擎 | 能做什么？绝对不可？ | 约束集 + 执行器 |
| | 意图/行为系统 | 目标+计划+状态机 | 想做什么？如何达成？ | 目标层次 + 计划队列 |
| | 价值/情感系统 | 效用+情感状态机 | 什么值得？偏好排序？ | 效用向量 + 情感状态 |

**关键区分**:
- **四棵数据结构底座**是**持久化的、可查询的、版本化的**存储结构。没有它们，世界无法被精确回溯。
- **三大业务逻辑系统**是**运行时的、瞬态的、可重新计算的**执行逻辑。它们消费数据结构底座，驱动世界演化。

## 4. 数据结构底座（四棵硬骨架）

四棵树构成世界的**最小可行认知系统**。没有它们，世界无法被精确查询和审计。

### 4.1 语义图谱树（Ontology Tree）

- **职责**: 定义世界中的概念、类型、属性及推理规则。
- **数据形态**: 有向图（RDF/属性图）。节点为概念/实例，边为关系。
- **关键设计**:
  - 与实体树解耦：语义树存"`AttackEvent` 是 `CombatAction` 的子类"，实体树存"`Entity-42` 在 `t` 时刻执行了一次攻击"。
  - 支持规则推理："所有 `CombatAction` 可能触发 `Aggro` 状态"。
- **静态性**: 运行时只读，变更需版本化重启或热更新。

### 4.2 实体搜索树（Entity Tree）

- **职责**: 管理世界中的全部可辨识对象（人、物、组织、抽象概念实例）。
- **数据形态**: 以 `entityId` 为主键的索引结构（HashMap / B+树）。
- **关键设计**:
  - 每个实体持有跨树指针：`semanticTypeId`, `spatialAnchorId`, `currentGoalId` 等。
  - 支持模糊检索（名称/标签）与精确检索（ID）的双路径。
- **示例**:
  ```json
  {
    "entityId": "NPC-7",
    "name": "哨兵",
    "typeRef": "Guard",
    "spatialAnchorId": "Anchor-Block-A",
    "state": { "health": 100, "posture": "alert" },
    "eventHistory": ["Evt-7721", "Evt-7723"]
  }
  ```

- **实现指引**: 本树的落地实现见子系统文档
  [`entity/`](entity/README.md)（设计文档 / 使用文档齐备）。实现要点:
  实体 = 从属性观测流中浮现的推论（Observation → 时空窗口侧写 → 归并
  视图），侧写镜像永久保留，合并/拆分以 append-only 绑定表达（latest
  wins、全历史可审计），实体级可信度支持半衰期衰减，时间桶支持多分辨率
  上卷，合并前做轨迹连续性（vmax 物理可达）校验；存储跑在统一存储层
  （storage/entitytree），空间锚点语义由 geocore 路径码提供。

### 4.3 时空索引树（Spatiotemporal Tree）

- **职责**: 索引实体在时空中的位置与轨迹，支持范围查询与邻近查询。
- **数据形态**: 分层空间索引（八叉树/27叉树/R-tree）+ 时间版本链。
- **关键设计**:
  - **锚点系统（Anchor）**: 支持多坐标系（直角/球面/极坐标/运动坐标系）。锚点本身可被索引管理，支持跨场景切换。
  - **时间维度**: 支持 `AS OF t` 时间旅行查询。历史状态可通过事件树回溯或显式快照存储。
  - **边界条件索引**: 对于连续场（如电磁场），不存储场数据，只存储影响场的**离散实体**（信号源、障碍物）及其参数。

### 4.4 事件因果树（Causal Event Tree）

- **职责**: 记录世界的全部状态变更及其因果关系，支持回溯与反事实推演。
- **数据形态**: 有向无环图（DAG），节点为事件，边为因果/时序关系。
- **关键设计**:
  - **事件节点**:
    ```json
    {
      "eventId": "Evt-7723",
      "eventType": "WEAPON_DRAWN",
      "actorId": "Entity-42",
      "relatedEntities": ["Entity-7"],
      "spatiotemporalRef": "Anchor-7@169...",
      "causes": ["Evt-7701"],
      "effects": ["Evt-7724", "Evt-7725"],
      "probability": 1.0,
      "counterfactuals": []
    }
    ```
  - **反事实沙盒**: 从检查点克隆隔离世界副本，修改/删除目标事件，由物理/行为引擎重新推演，结果只读、不回流主世界。
  - **概率因果**: 对于混沌系统（如电磁干扰导致的通信中断），因果边附带置信度与统计分布，而非确定性断言。

## 5. 业务逻辑系统（三大软逻辑）

三大系统不是树结构，而是**运行时的执行逻辑**。它们消费四棵数据结构底座，驱动世界演化。

### 5.1 规则/约束系统（Rules & Constraints System）

- **本质**: 规则引擎 + 约束求解器，不是树结构。
- **职责**: 定义世界的绝对边界，是**合法性的最终仲裁者**。
- **分层**:
  - **物理规则**: 速度上限、能量守恒、空间曲率限制。
  - **系统规则**: 技能CD、资源公式、阵营声望机制。
  - **社会规范**: 贸易协议、宣战规则、外交礼仪。
- **不可妥协性**: 必须是100%确定性的符号系统。LLM可辅助生成规则DSL的初稿，但运行时零LLM参与。
- **与数据结构的关系**: 规则系统读取语义树中的概念定义，校验实体树中的状态变更，输出合法/非法判定。

### 5.2 意图/行为系统（Intention & Behavior System）

- **本质**: 目标层次结构 + 计划生成器 + 状态机，不是树结构。
- **职责**: 多智能体的目标分解、计划生成与冲突仲裁。
- **分层**:
  - **战略层**（分钟/小时级）: "征服星系" —— 可由LLM生成策略模板。
  - **战术层**（秒级）: "先集火治疗" —— 显式状态机执行，保证确定性。
  - **操作层**（帧级）: 走位、技能释放 —— 绝对禁止LLM介入，纯符号状态机。
- **与数据结构的关系**:
  - 读取实体树获取智能体当前状态。
  - 读取时空树获取环境信息（障碍物、敌人位置）。
  - 读取事件树获取历史因果（"上次被背叛过，所以这次不信任"）。
  - 生成的新意图作为**瞬态运行时对象**，不直接持久化为树结构；只有关键决策（如目标切换）才作为事件写入事件树。

### 5.3 价值/情感系统（Affect & Value System）

- **本质**: 效用函数 + 情感状态机，不是树结构。
- **职责**: 记录实体对事件/其他实体的主观态度与效用判断。
- **数据形态**:
  - 显式数值：`trust=0.73`, `fear=0.15`（存储在实体树的属性中）。
  - 情感标签：`hostile`, `friendly`, `neutral`。
- **与数据结构的关系**:
  - 数值存储在**实体树**的实体属性中（硬数据）。
  - 情感变化规则存储在**语义树**中（"背叛导致信任度下降0.5"）。
  - 情感变化事件写入**事件树**（"Entity-3对Entity-42的信任度从0.8降至0.3"）。
- **与LLM的边界**:
  - 显式数值保证长期一致性。
  - LLM负责将数值变化翻译为自然语言解释（"他因为上次被背叛而不再信任你"）。
  - LLM可在价值冲突时提供仲裁建议，但最终权重调整写入实体树。

## 6. 感知表征层（L2）

感知层负责将原始输入（视频、点云、传感器、自然语言）转化为**可供符号层消费的候选表征**。

| 感知器 | 输入 | 输出 | 技术形态 |
|--------|------|------|---------|
| **空间感知器** | 视频/点云/传感器流 | 3D场景图、占据网格、NeRF/Gaussian | 生成式视觉模型 |
| **时序感知器** | 连续帧/事件流 | 动作片段、关键帧、运动轨迹 | 视频理解模型 |
| **语义感知器** | 文本/语音/交互日志 | 结构化事件描述、意图标签 | LLM/NLP pipeline |
| **关系感知器** | 多实体交互画面 | 接触图、社交距离、势力范围 | 图神经网络 |

**关键原则**: 感知层是**概率性的、有损的**。它把混沌信号压缩成带置信度的候选表征（"可能是火箭，也可能是流星，置信度0.6/0.4"），推送给符号层做最终判定与存储。

## 7. 世界操作系统层（L0）

世界OS是世界的"运行时内核"，负责将静态的世界模型转化为动态的世界演化。

### 7.1 核心组件

#### 7.1.1 时钟调度器（Clock Scheduler）

世界不是单一时间线。支持多时钟域及其映射：

| 时钟域 | 粒度 | 用途 | 示例 |
|--------|------|------|------|
| **物理时钟** | 毫秒级 | 网络同步、超时判定、技能前摇 | "0.5秒前摇" |
| **逻辑时钟** | 离散tick | 状态帧推进、回合制结算 | "第3到第5逻辑帧" |
| **叙事时钟** | 弹性 | 情节节奏、章节推进 | "三年过去了" |
| **因果时钟** | Lamport/Vector | 分布式多智能体的happened-before判定 | 冲突仲裁 |

**时钟映射**: "技能前摇0.5秒"（物理）→ "占用第3-5逻辑帧"（逻辑）→ "叙事上属于蓄力阶段"（叙事）。

#### 7.1.2 事件总线（Event Bus）

世界状态变更的唯一合法来源。

```
感知输入 / 智能体决策 → 事件总线 → 规则系统校验 → 因果图插入 → 
状态管理器更新 → 时空索引刷新 → 实体树同步 → 通知订阅者
```

- **原子事件队列**: FIFO，严格时序。
- **因果事件图**: DAG，支持分支/合并。
- **反事实沙盒**: 隔离推演，不写入主世界。

#### 7.1.3 执行引擎（Execution Engine）

四引擎并行，优先级严格：

| 引擎 | 输入 | 输出 | 优先级 | LLM可否介入 |
|------|------|------|--------|------------|
| **规则引擎** | 待执行事件 + 规则系统 | 合法/非法，参数修正 | **最高** | ❌ 绝对禁止 |
| **物理引擎** | 合法事件 + 时空树 | 新状态（位置/速度/形态） | 高 | ⚠️ 生成式模型可替代场计算，但接口不变 |
| **行为引擎** | 实体状态 + 意图系统 | 下一动作/目标调整 | 中 | ⚠️ 高层策略可LLM生成，执行层禁止 |
| **叙事引擎** | 事件流 + 价值系统 | 情节节奏、视角切换 | 低 | ✅ 可由LLM驱动 |

**冲突解决**: 行为引擎想"NPC穿墙"，规则系统返回 `INVALID: collision constraint violated`。

#### 7.1.4 状态管理器（State Manager）

- **当前状态**: 内存中的热数据，四棵树的实时镜像。
- **WAL（Write-Ahead Log）**: 先写日志，再写内存，崩溃可恢复。
- **快照（Snapshot）**: 定期完整序列化，支持任意时刻回滚。
- **分支（Branch）**: 支持"世界线分叉"——从t时刻分裂出平行宇宙，用于A/B测试或多人平行宇宙。

#### 7.1.5 接口网关（Interface Gateway）

- **LLM适配器**: 自然语言 ↔ 符号操作（JSON/Protobuf）。
- **人类接口**: 可视化、调试、手动注入事件。
- **外部系统API**: 与其他世界或现实系统互联。

## 8. 连续系统的处理（以电磁场为例）

电磁场是连续、混沌的偏微分方程系统，**不进入符号树**。符号树只管理场中的**离散实体、事件与决策**。

### 8.1 分层处理

```
┌─────────────────────────────────────────┐
│  连续物理层（Field Engine）              │
│  传统：FDTD / 射线追踪                   │
│  现代：神经场模型 / 生成式信道预测        │
│  输出：场强分布、多径延迟、信噪比热力图   │
│  性质：混沌、连续、概率性                 │
└─────────────┬───────────────────────────┘
              │ 离散化接口（Field-to-Event Gateway）
┌─────────────▼───────────────────────────┐
│  符号树层（你的世界树）                   │
│  只存"场发生质变"的离散事件和实体关系     │
└─────────────────────────────────────────┘
```

### 8.2 符号树的具体职责

| 树 | 存储内容 | 不存储内容 |
|---|---|---|
| **空间索引树** | 信号源位置/参数、障碍物几何/材质 | 每一点的场强值 |
| **实体搜索树** | 通信设备（手机/基站/无人机）的协议/频段/灵敏度 | 实时接收信号质量 |
| **事件因果树** | `LINK_ESTABLISHED`, `SIGNAL_DEGRADED`, `HANDOVER` | 场强渐变过程 |
| **语义图谱树** | `5GHz` `is-a` `微波`, `钢筋混凝土` `causes` `衰减` | 具体衰减数值 |

### 8.3 场-事件转换器（Field-to-Event Gateway）

物理引擎每帧输出场数据，网关只在**观测点**采样并检测阈值跨越：

```
采样位置：通信设备接收端、预设监测点
阈值检查：
  - RSSI 跨越 -90dBm？ → 生成 SIGNAL_DEGRADED
  - SNR 从 >20dB 跌到 <10dB？ → 生成 INTERFERENCE_DETECTED
  - 多径延迟超过均衡器容忍？ → 生成 LINK_UNSTABLE
事件写入事件因果树 → 触发后续逻辑（切换基站/启动抗干扰/标记盲区）
```

### 8.4 反事实与混沌

对于"如果移除Building-15，信号如何？"：

- 物理引擎（传统或生成式）重跑仿真。
- 结果不是确定性因果链，而是**概率分布**。
- 事件树记录为 `CounterfactualNode`，附带 `resultDistribution` 与 `confidence: statistical`。

**符号树承认混沌的存在**，但不试图用树结构模拟场本身。

## 9. 生成式模型融合

### 9.1 生成式模型替代物理引擎

生成式模型（NeRF/3DGS/神经信道预测）正在替代传统场计算的"白箱方程"，但**接口边界不变**。

```cpp
// 旧接口：确定性物理引擎
class PhysicsEngine {
    Field computeField(Scene scene, Source source);
}

// 新接口：生成式场模型
class GenerativeFieldModel {
    ProbabilisticField inferField(Scene scene, Source source);
    // 输出的是场强分布，不是确定值
}

// 不变：场到事件的离散化网关
class FieldEventGateway {
    Event[] sampleEvents(ProbabilisticField field, List<Entity> observers);
}
```

### 9.2 生成式模型本身也需要被符号树管理

| 管理内容 | 存储位置 | 原因 |
|----------|---------|------|
| 模型版本号 | 实体树/语义树 | "v2.1在5GHz场景下比v1.7更准确" |
| 训练数据范围 | 语义树 | "该模型只在城市密集区训练过" |
| 置信度阈值 | 规则系统 | "输出方差>0.3时降级为传统射线追踪" |
| 预测归因 | 事件树 | "本次链路中断预测由模型A做出" |

### 9.3 LLM 的精确位置

LLM不是世界模型本身，而是**世界模型的操作员和翻译官**。

```
用户输入："让NPC-7去火星基地"
    ↓
[LLM适配器] 解析为符号指令
    ↓
{ actor: "NPC-7", action: "MOVE", target: "Anchor-Mars-Base" }
    ↓
[世界OS] 规则校验 → 物理推演 → 状态更新 → 事件记录
    ↓
[LLM叙事层] 生成描述："火星的沙尘暴比预计的早到了"
    ↓
输出层：渲染/文本/音效
```

**铁律**: LLM生成的计划、对话、描述，必须经过世界OS的**规则系统校验**后才能生效。LLM可以建议，但规则系统拥有**最终否决权**。

## 10. 数据流全景

一个完整的"智能体行动"在世界中的流动：

```
[感知层] 摄像头/传感器/用户输入
    ↓
"看到玩家A在坐标X拔出了武器"
    ↓
[LLM适配器] 解析为符号事件
    ↓
{ eventType: WEAPON_DRAWN, actor: Entity-42, location: Anchor-7, timestamp: 169... }
    ↓
[事件总线] 接收事件
    ↓
[规则系统] 查规则：该区域是否允许拔武器？
    ├─ 否 → 事件被拒绝，生成违规记录
    └─ 是 → 事件合法，继续
    ↓
[物理引擎] 更新实体-42的状态（武器=拔出，姿态=战斗预备）
    ↓
[时空索引树] 刷新坐标，更新占据网格
    ↓
[实体搜索树] 同步实体-42的当前状态
    ↓
[事件因果树] 插入节点，建立因果边：WEAPON_DRAWN → 周围NPC进入ALERT状态
    ↓
[行为系统] 遍历受影响实体（周围NPC）
    ├─ 查意图系统：NPC-3的当前目标是"巡逻"
    ├─ 查价值系统：NPC-3对玩家A的信任度=-0.6，恐惧度=0.3
    └─ 生成新意图：NPC-3切换目标为"隐蔽观察"，并上报上级
    ↓
[状态管理器] 提交事务，写WAL，更新内存
    ↓
[LLM叙事层] 生成描述："你拔出枪的瞬间，街角的守卫猛地缩回了阴影里"
    ↓
[输出层] 渲染画面 / 返回文本 / 触发音效
```

## 11. 演进路线

| 阶段 | 目标 | 关键动作 |
|------|------|---------|
| **P0 骨架** | 世界可查询、可定位、可回溯 | 四棵数据结构底座跑通 |
| **P1 约束** | 世界有边界 | 加入规则系统（硬约束） |
| **P2 感知** | 世界能看懂输入 | 接入LLM适配器 + 生成式场模型 |
| **P3 能动** | 世界有自主性 | 加入意图/行为系统 + 价值/情感系统 |
| **P4 并行** | 世界可分叉 | 状态管理器支持分支与平行宇宙 |
| **P5 互联** | 世界可对外连接 | 接口网关对接外部系统与真实世界 |

## 附录：核心设计原则

1. **四棵硬树不可压缩**: 语义、实体、时空、事件是世界的最小数据结构底座，缺一不可。
2. **三大软逻辑可渐进**: 规则、意图、价值是业务逻辑系统，初期可用脚本/LLM模拟，需要精确控制时再硬化。
3. **确定性底座**: 任何涉及状态变更、规则校验、因果回溯的模块，必须是符号化的、可审计的。
4. **概率性感知**: 生成式模型负责"看懂世界"，但看懂的结果必须经过离散化网关才能进入符号层。
5. **LLM不碰状态**: LLM可以建议、解释、生成，但世界状态的最终写入权只属于世界OS。
6. **混沌封装**: 连续系统（电磁场、流体、人群）的混沌性被封装在物理引擎/生成式模型的黑箱内，符号树只消费其离散跃迁事件。
7. **多时钟域**: 承认世界不是单一时间线，不同子系统按各自时钟演化，通过映射层协调。
