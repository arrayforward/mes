# 实体搜索树子系统 设计文档

> 版本：v1.0
> 定位：世界模型四棵硬骨架之一"实体搜索树"的实现（《世界模型与世界操作系统
> 架构说明书 v2》§4.2）。本文面向需要理解系统内部机制的开发者与调参工程师；
> 上层调用方请直接读 [使用文档.md](使用文档.md)。

## 1. 设计思想

实体不是预先声明的对象，而是从属性观测流中**浮现**的推论。

制造业现场的现实是：没有谁会先登记"这是一辆车、车牌沪A12345"再开始观测。
摄像头、地磁、LLM 摘要、人工点检持续吐出碎片化的属性证据（"1 号门 t=100
看到车牌沪A12345"），系统要做的是把证据聚成束、让"存在某个实体"这个推论
自己长出来，并且在证据误判时可以被纠正——且纠正过程本身也留下记录。

由此导出三条设计公理：

1. **事实与解释分离**。观测（事实层）永不修改；实体归并（解释层）是缓存，
   随时可从事实重建。与 eventstore"侧写不可变、Binding 可追加纠正"
   一脉相承。
2. **append-only 铁律**。观测与绑定只有追加。合并/拆分不是修改，而是追加
   一条新的绑定记录（latest wins），全历史可审计——这是制造业质量追溯的
   硬要求。
3. **公式简单可解释、参数可配置**。所有打分公式都是一线工程师能心算验证
   的初等式子；所有阈值集中在 `ResolverConfig`，不进代码。

## 2. 三层模型

```
Observation（属性观测：最小证据单元，append-only，永不修改）
    observation_id / attribute_key / value / confidence /
    source_id / anchor_ref / timestamp / event_ref / seq
        │  按 (anchor_ref, timestamp / bucket_size) 时空窗口聚合
        ▼
AttrProfile（侧写：时空窗口内的属性包聚合，镜像永久保留）
    profile_id / anchor_ref / time_bucket / level(时间桶层级,0=最细) /
    attributes / info_score / status(pool → emerged → linked) / seq
        │  达 θ_form 浮现后 resolve：绑定到既有实体或新建实体
        ▼
EntityNode（实体：侧写的归并视图 merged view，当前态可变的缓存）
    entity_id / name / type / attributes / view_version /
    credibility(基准值) / status(candidate|confirmed|disputed) / updated_at(基准时间)

EntityBinding（侧写→实体绑定，append-only，latest wins）
    binding_id / profile_id / entity_id / confidence / kind(merge|split|manual) /
    note / seq
SourceRecord（来源可靠性，entitytree ↔ stmb 共享）
    source_id / reliability(0~1) / updated_at / meta
```

三层各自的可变性是刻意的：

| 层 | 可变性 | 理由 |
|---|---|---|
| Observation | append-only | 证据不可篡改 |
| EntityBinding | append-only | 解释可纠正，纠正留痕 |
| AttrProfile | upsert（镜像保留） | 同一窗口持续积累观测，属性包就地生长 |
| EntityNode | upsert | merged view 是缓存，真相在观测与绑定里 |
| SourceRecord | upsert | 来源画像随运行演化 |

## 3. 职责边界

```
entity 组件    算法与变化逻辑：浮现/合并/拆分/检索排序/时效衰减/来源闭环
               （entity::Resolver，只依赖 EntityStore 接口与 geocore 纯函数）
storage       增删改查：7 张表落地、索引维护、append-only 约束、
               有效绑定语义（RecordBackend 统一层，六后端）
geocore       空间语义：AnchorPath 路径码纯函数
               （ParseAnchorPath / ToString / IsPrefixOf / LcaDepth）
```

存储层为算法层提供的两处专门支撑：

- `EntityNode.updated_at`：credibility 的**基准时间**（秒）= 最近一次重建时
  全部有效侧写中最新的观测时间。stmb 纪律——查询返回有效值、存储基准值
  不改写，衰减只在查询时由 entity 组件计算。
- `et_sources`：来源可靠性表，与 stmb 观测管线仲裁共享（详见 §4.7）。

## 4. 核心算法

### 4.1 浮现：info_score 与 θ_form

观测按 `(anchor_ref, timestamp / bucket_size)` 聚合进侧写，每摄入一条重算：

```
info_score = Σ_key  weight(key) × log1p(该 key 下不同 source_id 的数目)
```

直觉：

- **同源重复边际递减**：同一摄像头重复报同一属性，log1p 让第 2、3 次几乎
  不加分——防止单个话痨来源刷出假实体；
- **多源互证加分**：两个独立来源看到同一属性，信息量实质增长；
- **稀有属性权重高**：`attribute_weight`（缺省 1.0）表达属性区分度，
  车牌（建议 3.0）比颜色（1.0）更能标识一个实体。

`info_score ≥ theta_form` 且侧写仍在 pool → 置 emerged 并触发 resolve。
info_score **只数来源数**，不乘置信度、不乘可靠性——保持简单；
置信度与可靠性的影响全部走 credibility 通道（§4.5、§4.7）。

### 4.2 Blocking：候选实体召回

两路召回取并集：

- **属性倒排**：侧写中每个 (attribute_key, value) 经 `et_profile_attrs`
  等值查询找到共享该值的其它已绑定侧写 → 其有效绑定所属实体；
- **锚点层级邻近**：±1 时间桶内的侧写，锚点满足以下任一即邻近
  （anchor_ref 按 geocore AnchorPath 路径码解析）：
  - 同一锚点（路径相等）；
  - 祖先/后代锚点（`IsPrefixOf`——侧写在"房间"、实体在"楼"也算邻近）；
  - LCA 邻近：`LcaDepth(a,b) ≥ min_lca_depth`（默认 0 = 只要求同根；
    生产建议 ≥1）。
  anchor_ref 不是合法路径码时**降级为字符串等值**，旧数据行为不变。
- **多分辨率回退**：锚点召回先查 level 0 细桶（±1 桶），无候选时逐级
  回退到更粗 level 的时间桶（粗桶覆盖更长时间跨度，常驻实体在观测稀疏
  时仍可召回），找到候选即停。单级配置（默认）恒只查 level 0。

### 4.3 候选打分与三区间决策

对召回的候选实体逐个打分：

```
对每个侧写与实体共有的 attribute_key（实体无此 key 不计入）：
    值匹配  pos += w(key) × 命中值数 / 侧写该 key 去重值数
    值冲突  neg += w(key)
norm = 共有 key 的权重和
c = norm > 0 ? ((pos − neg)/norm + 1)/2 : 0.5     // [-1,1] 映射到 [0,1]，
                                                  // 无共有 key 中性 0.5
score = clamp01(c + min(0.15, 0.05 × 侧写带来的新独立来源数))
```

决策：

| score 区间 | 动作 |
|---|---|
| ≥ theta_merge（默认 0.75） | 追加 merge 绑定（confidence=score），重建实体，侧写 → linked |
| ≤ theta_split（默认 0.30） | 新建实体（candidate），初始绑定置信度 = 有效置信度均值 |
| 两者之间（存疑区） | 侧写保持 emerged 等更多证据；最优候选实体标 disputed |

存疑区是刻意设计：**证据不足以合并、也不足以断言是新实体时，系统不乱动**，
把候选实体标记为"有争议"，留给更多观测或人工/LLM 干预。

### 4.4 合并与拆分语义

- **合并**：追加 kind="merge" 的 EntityBinding；目标实体重建 merged view
  （聚合全部有效 level 0 细桶侧写的属性，值按有效置信度加权求和——
  rollup 粗桶侧写是派生镜像不计入，见 §4.8），view_version +1；
  两个侧写镜像都永久保留，`profiles_of_entity` 返回 2 个。
- **拆分**：`split(profile_id, new_entity_name)` 新建实体并追加 kind="split"
  的绑定指向它（latest wins），新旧实体各自重建。绑定历史（merge + split）
  全部保留可审计；被拆走侧写的来源触发可靠性下调（§4.7）。

### 4.5 credibility 合成

```
credibility = 全部有效绑定置信度的均值 × n / (1 + n)     // n = 独立来源数
```

- 绑定置信度：merge 绑定 = 合并 score；新建/split 绑定 = 侧写**有效置信度
  均值**（观测 confidence × 来源 reliability）。低可信/低可靠观测流浮现的
  实体天然可信度低；
- 多样性因子 `n/(1+n)`：单源实体封顶 0.5，双源 0.67，三源 0.75——
  多源互证直接体现在实体级可信度上。

### 4.6 半衰期衰减（stmb 纪律）

```
effective = base × 0.5 ^ ((now − updated_at) / half_life)
half_life ≤ 0 或 now ≤ updated_at  →  原样返回 base
```

- 实体级：`credibility_half_life`（秒，默认 0=不衰减），
  `effective_credibility(entity_id, now)` 与 search 排序使用；
- 属性级：`attribute_half_life[key]`（缺省 0=不衰减），search 中每个命中
  属性乘新鲜度因子 `0.5^((now − 该属性最新观测时间)/half_life[key])`
  （最新观测时间取自侧写属性条目的 `ts`）；
- **基准值永不因时间改写**：credibility 与 updated_at 只在重建时更新，
  衰减是查询时的纯计算。同一基准值，不同 now 得到不同有效值——
  "这个结论还新不新鲜"由提问时刻决定。

### 4.7 来源可靠性反馈闭环

- **共享**：`et_sources`（source_id → reliability 0~1，默认 1.0）与 stmb
  `SourceRegistry` 同形态；制造业单库部署（entitytree 与 voxelstore 指向
  同一数据库文件）即一份数据两方共用。stmb 侧注册表自 voxel
  formatVersion 6 起随快照/WAL 落盘，并有 `UnistoreSourceBridge`
  （`-DSTMB_WITH_UNISTORE=ON`）做双向同步（详见使用文档部署章节）；
- **使用**：有效置信度 = confidence × reliability（未注册按 1.0），
  进入绑定置信度、merged view 权重与 credibility 合成；
- **反馈**：merge 成功 → 被解析侧写涉及来源 +`source_reward`
  （默认 0.02，封顶 1.0）；split 发生 → 被拆侧写涉及来源 −`source_penalty`
  （默认 0.05，封底 0.05）。被系统验证正确的来源渐渐更受信任，
  被纠正过的来源渐渐被降权——来源画像随运行自学习，不需要人工维护。

### 4.8 多分辨率时间桶（bucket_sizes 梯子）

对齐 stmb LOD 的"分辨率梯子"思想（**level 方向相反**：entitytree 的
level 0 最细，stmb 的 level 0 最粗——两个系统各自约定，勿混淆）：

- `bucket_sizes`（如 {300, 3600, 86400}）声明桶长梯子；为空时退化为
  `bucket_size` 单级（向后兼容，既有行为逐位一致）。观测恒进 level 0 细桶；
- `rollup(entity_id, level)`（上卷）：把某实体在 level-1 层的全部已链接
  细桶侧写按 level 层粗桶分组，每组聚合出一个粗桶侧写（属性并集、保留各
  观测条目、info_score 重算、status=linked、level 记录在侧写上），追加
  指向同实体的 binding（kind="merge"，note 标 rollup）。**细桶镜像不销毁**；
  幂等（同粗桶已存在粗侧写则跳过），由上层维护任务周期性调用；
- **粗桶侧写是派生镜像，不是新证据**：rebuild_entity 聚合 merged view 与
  credibility 时只计 level 0 侧写，避免重复计分；
- 价值：常驻实体在观测稀疏（夜间无人经过）时，细桶 ±1 已无候选，粗桶
  （覆盖小时/天级跨度）仍能把它召回进 blocking。

### 4.9 轨迹连续性校验（vmax 物理可达）

合并打分前的物理约束（规则系统式否决）：候选实体最近侧写与当前侧写之间，
`距离 > max_speed × Δt` 即物理不可能（10km 外的车 60s 内不可能开过来）。

- `max_speed`（m/s，默认 0=关闭）；`trajectory_check`（"veto" 排除候选 /
  "penalty" score 乘 `trajectory_penalty`，默认 0.5）；Δt=0 时任何
  d>0 即违反；
- 距离由 **DistanceProvider** 注入（`set_distance_provider`）：两锚点同一
  参考系下直线距离（米），返回 nullopt = 无数据**不约束**（不是判负）；
- veto：该候选直接排除；全部候选被否决 → 新建实体。penalty：把高分候选
  压进存疑区（标 disputed 等更多证据）——拿不准的场景用 penalty，
  强物理场景（车辆跨厂区）用 veto；
- 适配器 `entity/geocore_distance.h` 的 `make_geocore_distance(kernel, t)`
  把 geocore::Kernel 包装成 DistanceProvider（Convert 自带场景仲裁；
  解析失败/无法换算 → nullopt）。

### 4.10 search 检索排序

```
召回：find_entities_by_attribute 多路等值查询取并集（同 key 不重复计分）
match_score = Σ 命中 key 的 w(key) × 新鲜度因子 / Σ 查询 key 的 w(key)
final = alpha × match_score + beta × effective_credibility
```

按 final 降序取 topk；有效 credibility < min_credibility 的实体被过滤。
`now = 0`（默认）时不启用时效语义，与不加衰减的行为逐位一致。
每个命中返回 `explanation`（key / value / weight / freshness / latest_ts），
可逐属性解释"为什么是它"。

## 5. 存储层：7 表映射与 append-only

| 表 | 主键 | 性质 | 二级索引 |
|---|---|---|---|
| `et_observations` | seq（自增） | append-only | observation_id / attribute_key / anchor_ref / source_id |
| `et_profiles` | profile_id | upsert | anchor_ref / time_bucket / status / level |
| `et_profile_attrs` | id（自增） | 倒排索引 | profile_id / (attribute_key, value) |
| `et_entities` | entity_id | upsert | status |
| `et_entity_attrs` | id（自增） | 倒排索引 | entity_id / (attribute_key, value) |
| `et_bindings` | seq（自增） | append-only | binding_id / profile_id / entity_id |
| `et_sources` | source_id | upsert | — |

设计要点（与 eventstore 同一套索引哲学）：

- **可检索的语义不进 JSON 列**：侧写/实体属性拆倒排索引表，"按 (key,value)
  召回"在所有后端上都是普通等值查询，不依赖某个数据库特有的 JSON 函数；
- 倒排索引随 upsert **整组替换**（删旧插新）——merged view 重建后旧值
  立即不可命中；
- append-only 表（观测/绑定）的索引只增不改，一次写入、多次索引；
- 有效绑定 = 该侧写 seq 最新的一条（latest wins）；`profiles_of_entity`
  是"有效绑定"语义——被拆分纠正走的侧写不再返回，但其绑定历史完整保留。

## 6. 阈值调参指导

| 参数 | 实际语义 | 调高 | 调低 | 制造业建议起点 |
|---|---|---|---|---|
| `bucket_size`（300s） | 侧写时空窗口的时间粒度 | 窗口大：跨时间证据更易聚一起，但不同对象易混 | 窗口小：侧写碎、浮现慢 | 摄像头巡检节拍 5 分钟 → 300 |
| `theta_form`（3.0） | 浮现所需信息量 | 实体浮现保守，弱证据被压下 | 噪声也能造出实体 | 3.0；单源密集场景可降到 2.0 |
| `theta_merge`（0.75） | 合并所需证据强度 | 合并保守，同款不同物易被拆开（实体偏多） | 激进合并，误合并增多（靠 split 兜底） | 0.75；强标识（车牌/序列号）主导时可 0.7 |
| `theta_split`（0.30） | 新建实体的证据下限 | 更多侧写落入存疑区等证据 | 轻易新建，实体库膨胀 | 0.30 |
| `min_lca_depth`（0） | 锚点 LCA 邻近门槛 | 只有近亲锚点才算邻近，召回收窄 | 远亲锚点也召回，打分负担重 | 生产 ≥1（同根不同子区不算邻近） |
| `attribute_weight` | 属性区分度 | 强标识主导合并与检索 | 弱属性噪声放大 | 车牌/序列号 3.0，描述性属性 1.0 |
| `alpha / beta`（0.7/0.3） | 检索排序中匹配度/可信度配比 | α 高：像谁就排谁（调查场景） | β 高：谁可信排谁（决策场景） | 调查 0.8/0.2，决策 0.5/0.5 |
| `credibility_half_life`（0） | 实体可信度保鲜期 | 不衰减（默认） | 越短越"喜新厌旧" | 车间日级变化 → 86400 起试 |
| `attribute_half_life` | 属性级保鲜期 | 不衰减（默认） | 易变属性（位置/温度）单独设短 | 静态属性不设，动态属性按变化周期 |
| `source_reward / source_penalty`（0.02/0.05） | 来源奖惩步长 | 奖惩过敏，可靠性震荡 | 学习慢 | 惩罚 > 奖励（错一次要多次正确补回） |
| `bucket_sizes`（空=单级） | 时间桶分辨率梯子（level 0 最细） | 级多：稀疏期召回好，存储多 | 级少：简单 | {300, 3600, 86400}（5分/1时/1天） |
| `max_speed`（0=关闭） | 轨迹物理可达上限（m/s） | 过松：不可能合并漏网 | 过紧：合法合并被误杀 | 车辆 20~40，人 2，AGV 5 |
| `trajectory_check`（"veto"） | 违反时 veto 排除 / penalty 压分 | veto：硬约束 | penalty：留存疑余地 | 强物理场景 veto，拿不准 penalty |
| `trajectory_penalty`（0.5） | penalty 模式压分因子 | 越低压得越狠（进存疑区） | 越高越接近不罚 | 0.5（压到 θ_merge 之下） |

调参纪律：**先定性后定量**——用 demo_entity 级别的剧本（已知正确答案的
观测流）验证阈值方向，再上真实流量；θ_merge/θ_split 之间的距离就是
系统"承认自己不确定"的宽度，不应为了追求自动化率而把它压成 0。
