1　概述与设计原则

本说明书是空间几何内核的可实现规范，面向 AI 编码代理与人类工程师：给出完整的数据结构定义、核心算法伪码、精度与并发纪律、API 契约及测试清单。实现语言不设限；伪码采用类 C++ 记号。

内核解决的目标问题：在层级化（可运动、可非欧）嵌套参考系下，对点目标进行定位、索引、迁移与半径近邻查询，尺度动态范围不受浮点限制。

1.1　设计原则

  1. 结构跟随变化率。变化越快的层结构越简单：对象层用扁平数组，几何层用编码 + 哈希，语义层用目录。
  2. 身份是函数，不是记录。无限细分的东西不能被存储，只能被计算：锚点身份 = 路径码 = 坐标的纯函数。
  3. 静止换一切。拓扑静止是最大资产：它换来缓存合法化、零存储细分、无再平衡、离线烘焙。
  4. 非欧不出边界。任何几何奇异（球面、弧长、周期角）都封装在场景内，跨边界一律欧氏化。
  5. 精度是纪律，不是运气。平移精度靠层级、角度精度靠取模、合成精度靠链长控制，全部以强制纪律落实。

2　术语、公理与不变式

2.1　术语

术语表
术语定义
锚点（Anchor）带局部坐标系的空间区域；树中节点；分语义锚点（手工、命名、可动）与匿名锚点（规则细分、静止）

2.2　公理（不可违反）

A1 拓扑静止。锚点父子关系创建后不变；运动只改变变换参数。
A2 单归属。任一对象任一时刻恰有一条归属路径；对象挂在尺度恰好容纳它的最深节点。
A3 运动局限于语义节点。匿名节点相对其父静止（无旋转、规则平移），保证路径码可计算。
A4 边界欧氏化。非欧性不穿透场景边界；跨边界一律换算为父场景坐标。

2.3　不变式（每次写操作后必须成立）

  1. INV-1 物化最小性：哈希表中恰有"含对象或含物化子节点"的路径；空物化节点可回收（惰性）。
  2. INV-2 归属最深性：对象的归属路径是其尺度可容纳的最深节点；Find 无需跨层去重。
  3. INV-3 坐标原生性：对象坐标以其所属场景的 CoordinateModel 原生形式存储且已 Normalize。
  4. INV-4 缓存一致性：变换缓存的失效条件 = 路径变更或帧切换；任何写入路径不得读旧帧缓存。
  5. INV-5 迁移原子性：Transfer 先写新桶后删旧桶，任意并发读取至少在一处可见对象。

3　核心数据结构

3.1　路径码 AnchorPath

// 变长层级路径。codes[i] 为第 i 层子区编号（欧氏场景为 Morton 位组 0..7）。
// 定长上限 MAX_DEPTH（如 32）时可用定长数组 + depth，避免堆分配。
struct AnchorPath {
    uint32_t codes[MAX_DEPTH];   // 或 SmallVector
    uint8_t  depth;

    AnchorPath Parent()      const;        // depth-1，O(1) 视图或拷贝
    AnchorPath Prefix(int d) const;        // 前 d 段
    bool       IsPrefixOf(const AnchorPath& other) const;
    uint64_t   HashKey() const;            // 定长编码的哈希键（深度打包进高位）
};
int LcaDepth(const AnchorPath& a, const AnchorPath& b);  // 最长公共前缀长度

编码建议：深度 ≤ 21 且每段 3 bit 时，可将整条路径打包进单个 uint64（深度置高位），哈希与比较退化为整数运算；含语义锚点命名段的场景，语义段用独立命名空间编号而非 Morton 位组。

3.2　运动学 Kinematic

struct Kinematic {
    enum class Type : uint8_t { Static, CircularOrbit, PathConstrained };

    // Static（匿名节点恒为此型的特例：origin 规则生成，rotation = 单位四元数）
    Vec3d      origin;
    Quaternion rotation;

    // CircularOrbit（行星等）
    double     orbitRadius;    // 轨道半径（父系单位）
    double     period;         // 公转周期（秒）——存周期不存角速度，见 P2
    double     phase0;         // 初始相位（圈数 [0,1)）
    Quaternion orbitalPlane;   // 轨道面朝向
    double     spinPeriod;     // 自转周期；0 = 不自转

    // PathConstrained（列车/飞机等一维约束）
    SplineId   path;           // 线路样条
    Timetable  timetable;      // s(t) 查询

    Vec3d      OriginAt(double t)   const;
    Quaternion RotationAt(double t) const;
    Vec3d      OriginVelAt(double t) const;   // 解析导数；Transfer 速度切换必需
};
Vec3d Kinematic::OriginAt(double t) const {           // CircularOrbit 分支
    double turns = fmod(phase0 + t / period, 1.0);    // P1：圈数取模
    if (turns < 0) turns += 1.0;
    double s, c;  sincos(2.0 * PI * turns, &s, &c);
    return orbitalPlane * Vec3d{orbitRadius * c, orbitRadius * s, 0.0};
}

4　核心算法

4.1　点定位 AnchorOf

算法 S1　AnchorOf（纯函数，O(d)）
AnchorPath AnchorOf(const Scene& sc, Vec3d p, double eps):
    path = sc.rootPath;  q = p
    while CellSize(sc.model, path) > eps:
        c    = sc.model.CellOf(q, path.depth + 1)   // Euclidean：右移位运算
        path = path.Append(c)
        q    = ChildLocalOffset(q, c)               // 进入子区局部坐标
    return path                                      // 不需查任何表

4.2　节点变换解析 TransformAt

算法 S2　TransformAt（虚拟/物化统一入口）
Transform TransformAt(const AnchorPath& path, double t, const FrameCache& fc):
    if (auto it = nodes_.find(path.HashKey()); it != nodes_.end())
        return { it->second.kinematic.OriginAt(t),
                 it->second.kinematic.RotationAt(t) };
    // 虚拟节点：规则生成（A3 保证可计算）
    seg   = path.LastSeg()
    parent = path.Parent()
    return { QuantizedChildOrigin(parent, seg), Quaternion::Identity() };

4.3　坐标换算 Convert

算法 S3　ConvertPoint / ConvertDirection（LCA 行走）
Vec3d ConvertPoint(AnchorPath from, AnchorPath to, Vec3d p, double t):
    lca = LcaDepth(from, to);  cur = from
    for (d = from.depth; d > lca; --d):            // 上行 子→父
        tr = TransformAt(cur, t, fc)
        p  = tr.rotation * p + tr.origin
        cur = cur.Parent()
    for (d = lca + 1; d <= to.depth; ++d):         // 下行 父→子
        tr = TransformAt(to.Prefix(d), t, fc)
        p  = tr.rotation.Conjugate() * (p - tr.origin)
    return p

4.4　跨场景换算

算法 S5　Convert（统一入口，含场景仲裁）
Vec3d Convert(AnchorPath from, AnchorPath to, Vec3d p, double t):
    sa = registry_.OwnerOf(from);  sb = registry_.OwnerOf(to)
    if (sa == sb) return ConvertPoint(from, to, p, t)
    lca = LcaDepth(from, to)
    if (lca >= min(from.depth, to.depth) - 2)      // 近亲：行走（LCA 深，精度好）
        return ConvertPoint(from, to, p, t)
    // 远亲：烘焙矩阵 O(1)
    pa = LocalToSceneRoot(sa, from, p, t)          // 场景内短行走
    return scenes_[sb].invRootTransform * (scenes_[sa].rootTransform * pa)

热场景对（如主场景↔常驻副本）缓存合成矩阵 $M_{B}^{-1}M_A$，跨场景换算降为一次矩阵乘法；缓存键 = (sa, sb)，失效条件 = 任一方 rootTransform 变更（注册事件驱动）。

4.5　近邻查询 Find

算法 S6　Find（两阶段：结构层收集 + 数据层过滤）
vector<ObjRef> Find(SceneId sid, AnchorPath ctx, Vec3d center, double radius,
                     double t, size_t topN = SIZE_MAX):
    const Scene& sc = scenes_[sid]
    // 阶段一
    base  = AnchorOf(sc, center, EpsFor(radius))          // S1
    cells = sc.model.NeighborCells(ChildLocal(center, base), radius)
    cand  = []
    for (c : cells)
        if (auto it = nodes_.find(base.ReplaceLastSegs(c).HashKey()); it != end)
            cand.append(it->second.bucket)                // 虚拟节点零成本跳过
    // 阶段二（平方域，延迟开方）
    r2 = radius * radius
    hits = [o | o ∈ cand, sc.model.DistanceSq(o.pos, center) ≤ r2]
    if (topN == SIZE_MAX) sort(hits, by DistanceSq)
    else                  partial_sort(hits, topN, by DistanceSq)
    return hits

跨场景 Find：先 Convert 查询中心到目标场景（S5），半径以边界点重估 $r' \approx r \cdot \|\partial \text{ToParent}/\partial x\|$（有界近似，需在文档中声明），再调 S6；祖先重叠由 INV-2 保证不产生重复命中。

4.6　迁移 Transfer 与增删

算法 S7　Transfer（先写后删，INV-5）
void Transfer(ObjectRecord& o, AnchorPath to, double t):
    p' = ConvertPoint   (o.anchor, to, o.pos, t)
    v' = ConvertVelocity(o.anchor, to, o.pos, o.vel, t)
    p' = SceneOf(to).model.Normalize(p')               // P4：写入即规范化
    BucketAt(to).Insert(o.id)                          // 1. 先写新
    BucketAt(o.anchor).Remove(o.id)                    // 2. 后删旧
    o.anchor = to; o.pos = p'; o.vel = v'              // 3. 提交归属

5　精度纪律

精度纪律一览（全部强制）
编号纪律机制违反后果
P1圈数取模相位存圈数，求值前 fmod(·,1.0)，sin/cos 参数恒在 $[0,2\pi)$长期运行后角度漂移
P2存周期不存角速度$t/T$ 一次除法代替 $\omega t$ 后取模相位误差放大一个量级
P3同一时刻求值一次换算链共享帧时间 $t$，由调用方传入运动链不封闭，变换不可逆
P4写入即规范化所有写入路径过 Normalize；读取不隐式修正脏坐标（$lon{=}181°$ 等）扩散
P5LCA 行走，不绕根换算链长 $= d_a+d_b-2\cdot\mathrm{lca}$，中间坐标不出相遇层尺度大数抵消，深空换算失真
P6局部类型降格节点半径 < 阈值（如 10 km）时对象坐标用 float32 存储（仅浪费存储带宽，可选）
P7平方域比较Find 过滤与排序用 DistanceSq，仅结果开方（性能损失，非正确性）
P8烘焙用 double 合成rootTransform 注册时以 double 全程连乘，一次落盘逐层截断误差累积进缓存

三通道误差模型（详见论文第 9 节）：平移误差界、角度误差界、合成误差界均只依赖链长与层级数，与世界绝对尺度无关。实现验收时应能以该模型逐通道归因任何超差。

6　并发模型

  • 读写锁：锚点树物化表与对象桶使用 shared_mutex——查询并发、写入互斥；桶级锁而非全局锁，锁粒度 = 物化节点。
  • 帧缓存线程化：FrameCache 每线程一份；BeginFrame 在主循环推进，写入方严禁跨帧复用（INV-4）。
  • Transfer 并发语义：先写后删保证任意读至少在一桶可见对象；查询方对"双桶短暂同见"的容忍由 INV-2 的查询路径唯一性兜底——同一查询路径只扫一桶，不会重复返回。
  • 注册表冻结窗口：场景注册/注销走 RCU 或停止世界窗口；查询热路径对注册表只读。
  • 路径码无锁友好：AnchorOf、LCA、Convert（纯行走部分）为无共享纯计算，天然可并行；锁只出现在 TransformAt 查表与桶扫描两处。

8　测试与验证清单

8.1　不变式测试

  1. T-INV-1：随机插入/删除 $10^6$ 次后，物化表恰好覆盖非空区域（无空洞、无冗余空节点，语义节点除外）。
  2. T-INV-2：任意对象，其子锚点不存在可容纳它的更深物化节点；Find 结果集无重复 id。
  3. T-INV-3：注入非法坐标（$lon{=}181°$、$s{<}0$），Save 后存储值必为规范化主值。
  4. T-INV-5：多线程并发 Transfer + Find 压测，无丢失对象、无重复返回、无死锁。

8.2　精度测试

  1. T-P1：圆轨道锚点 $t$ 推进 $10^9$ s 后，OriginAt 与 $t{=}0$ 同相位处偏差 < 机器精度 $\times$ 常数。
  2. T-P3/P5：往返换算一致性——随机锚点对，$\mathrm{Convert}(b,a,\mathrm{Convert}(a,b,p))$ 与 $p$ 的相对误差 < $10^{-12}$（同尺度局部），且绕 LCA 路径与绕根路径对比，前者误差严格不大于后者。
  3. T-P-尺度：在 $10^{11}$ m 锚点与 $10^{-2}$ m 锚点各放对象，互换算往返，相对误差不随路径两端尺度差恶化（误差只随链长增长）。

8.3　功能与场景测试

  1. T-F-邻域：跨 cell 边界的半径查询不漏对象（边界两侧各放对象对拍暴力结果）。
  2. T-F-球面：SphericalSurface 场景中，跨反经线（$lon{=}\pm180°$）的邻域展开正确；大圆距离与对拍一致。
  3. T-F-列车：MovingFrame1D 中对象驶出线路末端时触发段间 Transfer 或钳制，行为符合规格。
  4. T-F-休眠：目标场景 Dormant 时 Convert 仍正确（元数据可用），Find 返回"场景未加载"错误而非崩溃。
  5. T-F-速度：自转行星表面静止物体 Transfer 到轨道锚点后，速度包含表面线速度项（与解析解对拍）。

9　实现检查表与已知边界

9.1　实现检查表（按依赖序）

  1. AnchorPath：定长编码、Parent/Prefix/IsPrefixOf/HashKey、LcaDepth —— 全库地基，先行冻结。
  2. Kinematic：Static + CircularOrbit（PathConstrained 可后补），OriginAt/RotationAt/OriginVelAt + P1/P2。
  3. CoordinateModel：Euclidean3D 先行（variant 快路径），SphericalSurface 次之。
  4. 物化表 + TransformAt（虚拟/物化统一）+ 惰性物化链。
  5. ConvertPoint/Direction/Velocity（S3/S4）+ T-P 精度测试。
  6. 对象桶 + Save/Remove/Transfer（S7）+ INV 测试。
  7. Find（S6，平方域 + topN）。
  8. SceneRegistry（主表/名字/标签/SoA/OwnerOf）+ 跨场景 Convert（S5）+ 烘焙缓存。
  9. FrameCache 与并发模型（读写锁、RCU 窗口）。
  10. 性能基准与 P6 类型降格（可选优化）。

9.2　已知边界（不实现，属外围模块）

时空历史与预测查询、拓扑可达与路径规划、射线求交与连续碰撞、全配对检测、高维相似检索、分布式一致、位置不确定性——七类问题在本内核公理之外（见论文第 10 节），应作为挂接在场景树骨架上的外围模块另行设计；多视角正交划分（行政/功能/电磁）以辅助索引外挂，不入主树。
