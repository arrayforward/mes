## 1. 问题定义

大模型(LLM)做空间推理时有三个结构性短板:

1. **空间一致性**:语言模型没有内生的三维几何表示,物体在哪里、谁挡住
   谁、谁支撑谁,纯靠文本难以维持一致;
2. **精确几何**:坐标、区域包含、距离计算放到上下文里容易丢失精度;
3. **可验证的记忆**:一个事实是"谁在什么时候观测的、改过几次、以前是
   什么",LLM 自身无法回答也无法举证。

同时,真实世界的观测是**众源、带噪、有时效**的:多终端会看到同一物体,
旧数据会过期,昼夜/季节性的变化不应被当作"事实变更"。

因此需要的服务形态是:一个把「三维空间区域 + 时间点」作为一等公民的
**时空结构化记忆库**,具备可查询(空间+时间双维)、可回溯(版本历史)、
可信(多源仲裁)、可伸缩(分片与多尺度)、可接入(LLM 工具接口)的能力。

## 2. 设计目标

| 目标 | 对应能力 |
| --- | --- |
| 空间+时间双维索引与查询 | 空间格子索引 + 时间有序索引,服务层联合过滤 |
| 记忆可回溯、可举证 | 版本历史(生效区间),getAt 任意时刻回溯 |
| 海量对象与有限内存 | 分片存储(延迟加载/冷分片换出)+ 块级 LRU |

| 运动物体与静态环境分离 | 动态实例轨迹层 + 静止沉淀 |
| 众源观测的可信写入 | 变化分类 + 周期模式 + 加权仲裁 + 观察窗口 |
| 大模型可直接使用 | VQL + Function Calling + stmb_shell 联调 |
| 工程克制 | C++17、CMake、零第三方依赖(含 JSON 自实现) |

## 3. 从参考讨论到工程落地的映射

本项目源于一篇"语义体素网格作为大模型外部记忆"的技术讨论。其核心概念
与工程实现的对应关系:

| 参考讨论概念 | 工程落地 |
| --- | --- |
| 4D 时空立方体(空间 3D + 时间 1D) | `MemoryBlock{AABB region, TimeStamp timestamp}`,时空联合索引 |
| 体素(Voxel)离散化 | `SpatialGridIndex` 按 cellSize 分格哈希;`BlockKey` = 中心格子 + 时间槽 |
| 事实需要确认与演化 | 块状态机 `Pending → Stable → Changing → Stable`,候选变更确认生效 |
| 观测时效性 | `decayedConfidence` 半衰期衰减;`lastUpdate` 为起算点 |
| 历史分层保留 | `VersionLog`:生效区间 `[validFrom, validTo)`,淘汰/删除后历史默认保留 |
| Level-0(100km)→ Level-5(10cm)多尺度 | `levelCellSizes` 层级金字塔,粗层承载细层聚合摘要 |
| 运动物体不入静态网格 | `DynamicLayer` 动态实例(轨迹/来源/状态),静止后沉淀为静态块 |
| 众源观测管线 | `submitObservation`:六类变化分类 + 周期模式 + 加权仲裁 + 观察窗口 |
| VQL 查询语言 | `VqlEngine`:类 SQL 语法,含 AT 回溯与 SUMMARY 先粗后细 |
| 体素网格作为 LLM 外部记忆 | Function Calling 8 工具 + stmb_shell + DeepSeek 代理 |

## 4. 核心设计决策与取舍汇总

### 4.1 数据只存一份,索引只存引用

块数据只存在 `BlockStore` 一份;空间/时间索引只存 `BlockId`;版本历史按
id 归档。淘汰、删除、过期由服务层统一同步清理索引,**一致性集中在门面层
一把互斥锁下完成**,各部件自身尽量无锁(仅 BlockStore 可独立线程安全)。
取舍:简单可靠,牺牲细粒度并发。

### 4.2 空间索引是粗筛,精过滤在服务层

空间索引按格子离散化建倒排,查询只保证"不漏"(可能多给候选),精确相交
由 `AABB::intersects` 在服务层完成。格子边界上的块会被多算进相邻格子,
这对粗筛是安全的。取舍:索引逻辑极简,精度由服务层兜底。

### 4.3 版本历史默认保留,消亡块也可回溯

块被 LRU 淘汰、remove、expire 后,数据从 store 与索引清除,但 `VersionLog`
保留——"这里以前是什么"随时可查;`purgeHistory` 提供手动清理。取舍:以
少量内存换可举证性,这是"外部记忆"的核心价值。

### 4.4 置信度衰减只作用于返回副本

存储的基准置信度与 `lastUpdate` 永不改写;带 `now` 的查询/读取在返回副本
上计算 `base * 0.5^(elapsed/halfLife)`。取舍:衰减是纯函数,无后台任务,
无写放大。

### 4.5 快照 + WAL,不引外部数据库

持久化全部自实现:二进制帧(magic + 版本 + type/len/payload/CRC32),快照
用临时文件 + rename 原子写;WAL 记录操作,checkpoint 落快照并截断日志;
crash 导致的截断/CRC 错误尾部被丢弃、保留已验证前缀。取舍:格式可控、
零依赖,换来需要自行维护版本演进(formatVersion 1→5,每代不兼容并明确
声明)。

### 4.6 分片 = 持久层,全局组件 = 内存工作集

分片模式下,store/索引/VersionLog 仍是一个全局内存工作集,分片文件是
持久层。块级 LRU 淘汰的块标记"下沉(sunk)",flush 时与盘上旧数据归并。
查询触达的分片在查询窗口内 **pin 钉住**,防止"触达分片数超过驻留上限时
先加载的被挤出去导致漏查"。取舍:保留全部既有内存语义(全局容量、索引
行为不变),分片只解决"放得下"的问题;已知限制是单个分片不宜超过 store
容量。

### 4.7 动静分离,而不是把轨迹写进体素

运动物体若逐帧写入体素网格,会产生海量短命块并污染版本历史。动态实例
(ID/类别/bounds/速度/轨迹/来源)独立成层,Active → Stationary → Archived
推进,静止超时后由 `promoteStationary` 沉淀为静态层 Pending 块(走正常
确认流程)。取舍:动态层是易失态势(不记 WAL),静态层是沉淀事实。

### 4.8 观测管线把"写入"升级为"仲裁"

`submitObservation` 取代裸 put 成为众源写入入口:先按周期模式判 Seasonal,
再按现状一致性判确认,再进入候选-窗口-加权仲裁;未达阈值的候选挂起,
窗口内被反向观测推翻即 Transient 关闭,sweep 超时丢弃。两参 `confirm`
保留为"系统自确认(权重 1.0)",兼容旧语义。取舍:管线确定性可重放
(WAL 记录 Observe 与 Confirm 权重),但 SourceRegistry 不落盘(重启后需
重新登记,已在文档声明)。

### 4.9 接口层零依赖

VQL 与 Function Calling 的 JSON 为自实现迷你解析器;C++ 侧不做 HTTP
(WSL 无 libcurl),大模型联调走「stmb_shell(JSON Lines)+ Python urllib
代理」。取舍:多写几百行解析器,换来全工程零第三方依赖、全测试离线可跑。
